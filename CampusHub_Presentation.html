Why modern university ERP platforms require Polyglot Persistence

⚠️ Limitations of Single-Database Systems

  • Seat Overbooking Risk: Concurrent student self-enrollment requires strict ACID row-level locking (SELECT ... FOR UPDATE) that pure NoSQL lacks.
  • Mandatory Audit Compliance: Grade updates require database-level AFTER UPDATE triggers to guarantee an immutable history.
  • Rigid Schema Bottlenecks: Course announcements with multi-tag arrays and student reviews evolve rapidly and don't fit fixed relational columns.
  • High-Volume Session Rosters: Storing daily class attendance as 1 embedded MongoDB document per session avoids thousands of narrow join rows.

🗄️ MySQL 8.0 — System of Record (RDBMS)

  • Enforces 3NF schema & Foreign Key referential integrity
  • Controls course seat caps via ACID transactions
  • Computes Credit-Weighted GPA (4.0 scale) & SQL Views

🍃 MongoDB — Agility & Analytics (NoSQL)

  • Stores course_announcements with nested tag arrays
  • Aggregates course_feedback via $group & $avg
  • Archives attendance_sessions & student_transcripts

Advanced RDBMS Engineering

Triggers, Views & ACID Concurrency Control

Database-Level Automation & Transaction Safety in MySQL 8.0
05 / 12

Industry-Standard RDBMS Features

  • 4 Automated MySQL Audit Triggers: trg_grades_after_update, trg_grades_after_delete, trg_enrollments_after_update, and trg_enrollments_after_delete log old & new values into AuditLog.
  • 2 Analytical SQL Views: View_Student_Performance (5-table JOIN) and View_Course_Utilization (live seat fill %).
  • ACID Row Locking: Uses SELECT max_capacity FROM Courses WHERE course_id=%s FOR UPDATE during student enrollment.
  • 4.0 Weighted GPA Engine: Computes SUM(points × credits) / SUM(credits) across completed courses.

MongoDB Aggregation Pipeline in Action

  • $match Stage: Filters course_feedback documents by the instructor's assigned course IDs.
  • $group & $avg Stage: Groups documents by $course_id and computes live avg_rating and total_reviews.
  • $sort Stage: Orders courses by highest student rating.

Security & Data Integrity

Role-Based Access Control & Dual-DB Synchronization

How CampusHub Guarantees Security and Consistency Across MySQL & MongoDB
11 / 12

🔐 Enterprise Security & RBAC

  • Werkzeug PBKDF2 Password Hashing: Zero plaintext passwords stored in the Users table.
  • Strict Session Guard (@app.before_request): Enforces role isolation across Admin, Faculty, and Student routes and REST APIs.
  • 100% Parameterized SQL Queries: Prevents SQL Injection across all endpoints.
  • Automated Profile Binding: Dynamically links authenticated users to their Student or Faculty entity ID.

🔄 Real-Time MySQL ↔ MongoDB Sync

  • Attendance Sync: Saving attendance upserts rows into MySQL Attendance and writes a full class roster document to MongoDB attendance_sessions.
  • Audit Sync: Modifying a grade triggers MySQL AuditLog and appends a JSON event to MongoDB audit_logs.
  • Transcript Snapshot Sync: Opening a student transcript computes GPA from MySQL and upserts a JSON document into MongoDB student_transcripts.
