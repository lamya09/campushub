01 Executive Summary & Abstract

Modern academic enterprise platforms manage two fundamentally different classes of data: highly structured, transactional records that require strict relational integrity (enrollments, seat capacities, weighted GPA computation, and user credentials) alongside rapidly evolving, semi-structured data streams (course broadcast announcements, student course reviews, bulk session attendance rosters, and immutable academic transcript snapshots).

CampusHub solves this challenge by implementing an industry-standard Polyglot Persistence (Hybrid RDBMS + NoSQL) Architecture:

  • Relational Engine (MySQL 8.0): Enforces Third Normal Form (3NF) schema design, Foreign Key referential integrity, ACID row-level locking (SELECT ... FOR UPDATE) during self-service course registration, automated AFTER UPDATE / AFTER DELETE audit triggers, and pre-compiled analytical SQL Views.
  • NoSQL Document Platform (MongoDB — CampusHub_NoSQL): Stores schema-free JSON/BSON documents across 5 specialized collections (course_announcements, course_feedback, attendance_sessions, audit_logs, and student_transcripts) and leverages MongoDB Aggregation Pipelines ($match, $group, $avg) for real-time course rating analytics.
  • Multi-Portal Role-Based Web Application: Provides dedicated, isolated interfaces for Administrators, Faculty Members, and Students with end-to-end synchronization between both database engines.

02 Problem Statement & Justification for Hybrid Architecture

Relying exclusively on a single database paradigm introduces architectural bottlenecks in university ERP systems:

Architectural Challenge RDBMS-Only Limitation CampusHub Hybrid (MySQL + MongoDB) Solution
Concurrent Seat Registration Supported via ACID locks, whereas pure NoSQL lacks multi-table foreign key constraints. Handled in MySQL 8.0 using SELECT ... FOR UPDATE row locking and UNIQUE(student_id, course_id) constraints.
Course Announcements & Multi-Tag Broadcasts Requires auxiliary join tables for tags and rigid column migrations for priority metadata. Stored natively in MongoDB (course_announcements) as rich documents with embedded tag arrays.
Student Course Reviews & Star Ratings Rigid columns make optional review attributes and live rating aggregation cumbersome. Stored in MongoDB (course_feedback) and aggregated in real time via the $group and $avg pipeline stages.
Daily Session Attendance Rosters 12 courses × 40 sessions × 30 students generates 14,400+ narrow relational rows per semester. Synchronized into MongoDB (attendance_sessions) where one document encapsulates the entire class session and embedded student array.
Immutable Transcript Archival Requires 5-way SQL JOINs across Students, Enrollments, Courses, Grades, and Departments on every view. Archived in MongoDB (student_transcripts) as a self-contained JSON academic snapshot in a single read operation.

04 Relational Database Design (MySQL 8.0 — 3NF Schema)

The relational database CampusHub consists of 8 normalized tables designed in Third Normal Form (3NF) so that every non-key attribute is fully functionally dependent on the primary key and free of transitive dependencies:

4.1 Advanced Industry RDBMS Features Implemented

  1. Database Triggers (Automated Audit Logging): Four MySQL triggers (trg_grades_after_update, trg_grades_after_delete, trg_enrollments_after_update, trg_enrollments_after_delete) automatically intercept modifications at the database engine level and write old/new values into AuditLog.
  2. Analytical SQL Views: Pre-compiled views View_Student_Performance and View_Course_Utilization simplify multi-table reporting across 5 joined tables.
  3. Concurrency Control (ACID Transactions): Course self-enrollment uses SELECT max_capacity FROM Courses WHERE course_id = %s FOR UPDATE inside an explicit transaction to prevent race conditions when the last available seat is claimed.
  4. Weighted Cumulative GPA Engine (4.0 Scale): Computes credit-weighted GPA dynamically using the formula: GPA = SUM(grade_points × course_credits) / SUM(course_credits). 
-- Example: MySQL 8.0 AFTER UPDATE Trigger on Grades Table
CREATE TRIGGER trg_grades_after_update
AFTER UPDATE ON Grades
FOR EACH ROW
BEGIN
    IF OLD.grade <> NEW.grade OR OLD.marks <> NEW.marks THEN
        INSERT INTO AuditLog (table_name, record_id, action_type, old_value, new_value, description)
        VALUES (
            'Grades', NEW.grade_id, 'UPDATE',
            CONCAT('Grade: ', OLD.grade, ' (', OLD.marks, '%)'),
            CONCAT('Grade: ', NEW.grade, ' (', NEW.marks, '%)'),
            CONCAT('Updated grade for Enrollment #', NEW.enrollment_id)
        );
    END IF;
END;

05 NoSQL Document Store Architecture (MongoDB)

MongoDB Database Name: CampusHub_NoSQL — Engineered in mongo_db.py with dual-mode support (connects automatically to a live MongoDB daemon on mongodb://localhost:27017/ via pymongo, with zero-configuration local JSON document persistence in mongodb_data/ for portable evaluation).

5.1 The 5 MongoDB Document Collections

Collection Name Document Structure & Embedded Fields Real-Time Application Feature
course_announcements _id, course_id, course_name, faculty_name, title, message, priority, tags[], created_at Faculty post announcements with custom tag arrays; Students view live course broadcasts in their portal.
course_feedback _id, course_id, student_id, rating (1–5), difficulty, comment, would_recommend, tags[] Students submit star ratings & qualitative reviews; MongoDB Aggregation computes live average ratings for Faculty.
attendance_sessions _id, course_id, session_date, summary{present, absent, late}, records[{student_id, status}] Stores an entire class attendance roster in a single nested BSON document when Faculty click "Save Attendance".
audit_logs _id, event_type, actor, role, target_collection, metadata{}, timestamp Schema-free security and activity event stream capturing polymorphic metadata objects across all 3 portals.
student_transcripts _id, student_id, cumulative_gpa, standing, courses[{course_name, credits, grade, grade_points}] Self-contained, denormalized academic transcript snapshots generated whenever a student views their transcript.

// 2. MongoDB Aggregation Pipeline on CampusHub_NoSQL.course_feedback
db.course_feedback.aggregate([
  { "$match": { "course_id": { "$in": [1, 2, 11] } } },
  { "$group": {
      "_id": "$course_id",
      "course_name": { "$first": "$course_name" },
      "avg_rating": { "$avg": "$rating" },
      "total_reviews": { "$sum": 1 }
  }},
  { "$sort": { "avg_rating": -1 } }
])

06 Multi-Portal Role-Based Features

  • Admin Portal (/): Features a 2×2 Executive Bento Grid (Course Seat Utilization, Dean's List & Top Performers, Departmental Academic Pulse, Recent Course Enrollments), full CRUD across all entities, an automated ⚡ Audit Trail viewer, and an interactive 🍃 MongoDB NoSQL Store Explorer with live JSON inspection and document insertion.
  • Faculty Portal (/faculty-portal): Allows instructors to view their assigned courses, grade student rosters (auto-calculating letter grades), record batch session attendance (syncing to both MySQL and MongoDB), broadcast course announcements with tags, and inspect aggregated student feedback ratings.
  • Student Portal (/student-portal): Enables students to browse the course catalog with live seat progress bars, self-enroll or drop courses, track weighted GPA (4.0 scale) and print an official Academic Transcript, monitor per-course attendance percentages (with a < 75% shortage alert), read faculty announcements, and submit course reviews.

07 Conclusion

CampusHub demonstrates how combining MySQL 8.0 and MongoDB in a unified polyglot persistence architecture delivers the best of both database worlds: strict ACID transactional safety and 3NF relational integrity for core academic records, paired with high-velocity schema flexibility, nested document storage, and real-time aggregation pipelines for modern campus communication and analytics.
